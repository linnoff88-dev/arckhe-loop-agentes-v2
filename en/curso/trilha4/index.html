4.1~45 min

🔄 Stop prompting; design loops

The advanced-level shift: stop operating the agent and start designing the system that operates it.

What it is:

Steinberger: "don't prompt your agents—design loops that prompt your agents". The operator steps out; the system steps in.

Why learn:

It's the mental prerequisite for the entire track; without it, fleets and guardrails are just jargon.

Key concepts:

A loop that prompts the agent; the Cherny citation (via third parties).

What it is:

You replace yourself as the person writing prompts: you design the SYSTEM that does this instead of typing every turn.

Why learn:

Gets you out of the bottleneck; your time goes into design, not every iteration.

Key concepts:

Loop engineering; operator × architect.

What it is:

An agent that INFERS the loops you'd want (from your "vibe") and writes them. The highest rung on the abstraction ladder.

Why learn:

Tempting and risky: abstraction scales up and visibility goes down.

Key concepts:

Meta-agent; abstraction ladder.

What it is:

Osmani: a loop is a recursive goal—you define a purpose and the AI iterates until it completes it.

Why learn:

Every solid loop has 2 pillars: the goal (what) and verification (how it knows when to stop).

Key concepts:

Recursive objective; objective + verification.

What it is:

To run across multiple context windows, externalize the state: git + progress files (Anthropic's harness).

Why learn:

Each session: read the state, build 1 feature, self-verify, commit, leave things clean. The disk becomes long-term memory.

Key concepts:

Context window; externalized state; 1 feature per session.

What it is:

Nate Herk: just because Steinberger does this doesn’t mean it applies to you. There are cadence-based, event-driven, and 24/7 loops.

Why learn:

Not everyone needs 24/7—copying the fleet based on status is a mistake, not engineering.

Key concepts:

Cadence × event × 24-7; the right tool for your case.

4.2~55 min

🧱 Advanced patterns

The fleet pattern kit: Ralph loop, scheduled loops, worktrees, guardrails, adversarial verification, fan-out, and memory.

What it is:

Huntley/HumanLayer: an infinite shell loop that repeats the same prompt; each cycle mutates the code, which becomes the next starting state.

Why learn:

Powerful and dangerous: “bizarre emergent behavior” if it runs too long. Always combine it with guardrails.

Key concepts:

Ralph loop; the one-liner while :; do ...; done.

What it is:

Lewis (as reported): a job the agent repeats — wakes up on a schedule/event, reads the state, does 1 scoped job, writes it down, sleeps.

Why learn:

The manager classifies the backlog; the worker implements tasks and opens PRs; Issues as the control plane; a human approves the merge.

Key concepts:

Split manager/worker; control plane; fixed permissions.

What it is:

A worktree isolates parallel work; a sandbox isolates the environment; fixed permissions isolate what the agent CAN do.

Why learn:

Fixed permissions are how you let a loop run without doing something irreversible.

Key concepts:

Git worktree; sandbox; fixed permissions.

What it is:

Grassroots consensus: "the guardrails are the real work, not the agents." The worker opens a PR but never merges it; a human approves.

Why learn:

The agent is the easy part; the hard part is designing the boundaries around it.

Key concepts:

Guardrails; permissions prompt; final human gate.

What it is:

A second agent (or panel) that tries to BREAK the work, prompted to refute it. It approves only when it can’t.

Why learn:

The person doing the work never grades their own work—verification taken to the extreme.

Key concepts:

Verification specialist (speculation, not fact); refutation.

What it is:

A manager prompting agents that prompt agents ("Russian nesting dolls"). The pattern: orchestrate → delegate → verify.

Why learn:

Fan-out (A→N) adds speed; verification (N→1) prevents N errors from turning into a broken product.

Key concepts:

Fan-out; orchestration; A → N → 1.

What it is:

The loop spans episodes: act → feedback → reflect in text → save to episodic memory → do better next time.

Why learn:

Learns through language, not retraining. A worker that retains what it learned improves with every ticket.

Key concepts:

Cross-trial memory; Reflexion; episodic memory.

🛰️ Risks, cost, and case study

The course wrap-up: the real dangers of the autonomous loop, and how this very course was audited by a maker/checker loop.

What it is:

Osmani: hand over full control to the loop and stop reading the output. You remain the reviewer, especially at first.

Why learn:

The loop can’t sense when it’s drifting; you’re the missing sensor.

Key concepts:

Cognitive surrender; delegate with review × surrender.

What it is:

Firecrawl warns about cost and "comprehension debt." Sullivan rejects "tokenmaxxing" and "promptchud," too.

Why learn:

The middle ground: agents that reproduce real problems in your product.

Key concepts:

Comprehension debt; tokenmaxxing; promptchud.

What it is:

Nate: there have been 12h+ loops that weren’t useful. Useful ones usually run ~35 min to a few hours.

Why learn:

A "chunky loop before bed" (4–8h) can deliver; but you don’t need a 4-day loop.

Key concepts:

Duration scale; chunky overnight loop; drift.

What it is:

AI never gets it right on the first try; delegating the feedback-and-iteration cycle to AI makes quality improve much sooner.

Why learn:

It's why the risks are worth the cost: the curve reaches “good enough” sooner.

Key concepts:

Human line (slow) × loop line (fast) up to 90–95%.

What it is:

This course came out of a maker/checker loop: DISCOVER → EXTRACT (maker) → VERIFY (separate, adversarial checker) → SYNTHESIZE.

Why learn:

The model that FINDS the source never EVALUATES it — separating the roles is what builds trust.

Key concepts:

Pipeline discover→extract→verify→synthesize.

What it is:

Thumbnails (rubric + scorer), 3JS plane (render in the browser, ~37 min), Abbey Road in CSS (score ≥9 or cap at 8, stopped at V7), video editing (beats aligned).

Why learn:

In all of them, the bottleneck is the same: making verification objective enough to know when to stop.

Key concepts:

Concrete stop condition; dedicated scorer; pass cap.

What it is:

Use a loop for repetitive, reviewable, high-value tasks with a built-in checker. For everything else, prompt once.

Why learn:

Run loops at the right cadence for YOUR use case — not 24/7 for status. The course’s phrase: loop only with verification.

Key concepts:

“Do this / Skip this”; loop only with verification.
