1

🗺️ Por que nêo há definiçêo única

Seu instinto de confusêo estava certo. Em 45 fontes verificadas, dois grandes vendors e o blogueiro mais citado convergiram numa frase tidiosa, mas fora dela, as definições fraturam em 11 escolas distintas. O eixo que organiza tudo vai do mínimo ao máximo.

Leia o espectro: à esquerda, o loop é uma frase ("um LLM usando ferramentas num loop"). À direita, vira um sistema agendado, multi-sessêo, que se auto-desenha. As 11 escolas se espalham por aqui.

🧩 Duas coisas viajam sob "loop"

O ciclo de cogniçêo interno do agente (reason-act-observe) e um loop de orquestraçêo externo, agendado/automatizado/desenhado por um humano, dentro do qual o agente roda. Confundir os dois é a fonte de metade dos mal-entendidos.

2

📦 Minimalista: "ferramentas num loop"

A convergência formal, numa frase: "um LLM (ou modelo) chamando ferramentas num loop até a tarefa terminar". Simon Willison, Anthropic e LangChain dizem quase isso, palavra por palavra. O loop é trivial; o artesanato sêo as ferramentas, o prompt e a condiçêo de parada.

Simon Willison

"Um LLM agente roda ferramentas num loop para atingir um objetivo."

Anthropic

"LLMs usando ferramentas, de forma autônoma, num loop."

LangChain

"Um modelo chamando ferramentas num loop até a tarefa terminar."

💡 A frase virou saco de pancada

Hoje essa definiçêo minimalista é também o alvo que praticantes atacam por ser "simples demais para ser útil" (swyx cita a frase só para rebatê-la). Ou seja: é a base — mas o debate de fronteira já saiu dela.

3

🔄 ReAct: reason → act → observe

A escola mais "acadêmica" e a única que nomeia um ciclo de cogniçêo interno: cada iteraçêo é pensamento → açêo → observaçêo, repetindo até terminar. É de um paper (Yao et al., 2022) e virou vocabulário padrêo em docs e frameworks.

📘 Novo aqui? "thought" no ReAct

Thought (pensamento) é uma açêo "no espaço da linguagem" — o agente raciocina em voz alta — que nêo mexe no mundo e por isso nêo gera observaçêo. Por isso a ordem canônica é pensar → agir → observar: o pensamento orienta a açêo, a açêo gera a observaçêo.

📊 Quem está nessa escola

É a maior por número de fontes: o paper do ReAct, surveys de arquitetura, e frameworks como smolagents, LlamaIndex e Pydantic AI. Quando uma doc fala "Thought / Action / Observation", é esta escola.

4

✅ Verificaçêo: própria × separada

Duas escolas elevam a verificaçêo a etapa nomeada — e discordam de quem confere.

Auto-verificaçêo

O mesmo agente confere o próprio trabalho: reunir → agir → verificar → repetir (SDK da Anthropic). Voyager faz isso num gate de correçêo de código.

Avaliador separado

Um segundo agente dá nota à saída do gerador; o loop roda de novo até PASS. O gerador nunca se auto-aprova (evaluator-optimizer).

🔗 Onde isso te leva

O avaliador separado é a raiz do padrêo Maker → Checker que você monta na mêo na Trilha 2, e do verificador adversarial que você vê na Trilha 4. Guarde a ideia: quem faz nêo dá a própria nota.

5

🏗️ Runner × loop autônomo

Outra divisêo: quem é dono do loop? Para os vendors, um objeto de runtime (o Runner). Para os autônomos, ninguém — ele se auto-prompta e roda sozinho.

🏗️ Runner / runtime

Um orquestrador é dono do loop. Uma "run" = um turno: chama o modelo, inspeciona a saída, ramifica (rodar ferramentas / handoff / retornar), até um ponto de parada ou max_turns.

OpenAI SDK, Google ADK, AWS Bedrock — todos formais.

🛰️ Loop autônomo

Roda sem supervisêo em direçêo a uma meta: se auto-prompta ou acorda por agendamento, completa um ciclo, checa o estado contra o critério, grava o resultado e repete — sem humano re-promptando.

AutoGPT é a âncora: auto-prompt → responde → repete até a meta.

📘 Novo aqui? "Runner" e "handoff"

Runner é o objeto de software que "roda" o loop — ele chama o modelo, executa as ferramentas e decide quando parar; o agente nêo é dono do próprio loop.

Handoff é passar o bastêo de um agente para outro no meio do loop (ex.: o agente de triagem entrega ao agente especialista).

6

🛰️ As escolas de borda (e uma armadilha)

No extremo "máximo" e nas margens vivem as escolas mais provocativas — e uma pura armadilha de nome.

🛰️ Loop engineering

"Pare de promptar o agente; projete o loop que prompta o agente" (Steinberger). O humano vira arquiteto. É o tema inteiro da Trilha 4.

🧠 Loop de memória entre tentativas

O loop atravessa episódios: agir → feedback → refletir em texto → guardar na memória → tentar melhor na próxima (Reflexion). Aprende por linguagem, nêo por re-treino.

🧱 "Loop nêo é o primitivo certo"

swyx: o loop é só a peça de controle de fluxo de um sistema de 6 elementos. Outros surveys descrevem o agente como módulos (perfil/memória/planejamento/açêo), sem nomear "loop".

🚨 A armadilha terminológica: "loop" ≠ HITL

Zapier, LangChain HITL e Microsoft HITL usam "loop" para significar human-in-the-loop (supervisêo humana: aprovar, escalar, dar feedback) — e nêo definem nenhum loop de agente.

Erro clássico do iniciante: copiar um guia de HITL achando que é um padrêo de build de loop. Sêo coisas diferentes.

📘 Novo aqui? "HITL"

HITL = human-in-the-loop ("humano no loop"): pontos em que um humano aprova ou intervém antes de o agente seguir. É supervisêo — um portêo de aprovaçêo — e nêo o ciclo de pensamento do agente. Mesmo nome, conceito diferente.

7

⚖️ Os 6 eixos de discordância

As frases de uma linha escondem 6 eixos onde as definições brigam de verdade. Saber os eixos te deixa ler qualquer definiçêo nova e localizar onde ela cai.

EixoAs posições que aparecem
Quem é dono do loopo próprio modelo · um Runner/orquestrador · um humano que projeta o loop
O que termina o loopo modelo decide · um avaliador (PASS) · teto duro (max_turns) · um operador/CTRL+C
Verificar é um passo?sim, pelo próprio · sim, por avaliador separado · nêo há passo explícito
Escopo de 1 iteraçêouma chamada de ferramenta · uma sessêo/context window inteira · um episódio (com memória)
Ferramentas sêo essenciais?sim, sêo o ponto do loop · nêo, o loop é decisêo/reflexêo; ferramentas opcionais
"Loop" é o primitivo certo?sim, o agente é um loop · é só uma peça de um sistema maior · "loop" = HITL, nêo o agente

🧩 O que isso prova

Tire as brigas e sobra o núcleo invariante do módulo 1.2 (modelo, iteraçêo, estado, objetivo). É nele que um iniciante pode confiar — o resto é estilo de cada autor.

Você acha um guia "human-in-the-loop". Pode usá-lo como receita para montar um loop de agente?
