🪜 A escada de decisêo

1

🪜 A escada, em 2 perguntas

Construir um loop dá trabalho. Antes de investir esse trabalho, passe a tarefa por uma escada de decisêo de dois degraus. Só quando a resposta é SIM nos dois é que vale a pena construir um loop. Senêo, você gasta engenharia onde um prompt simples já bastava.

📘 Novo aqui? O que é "escada de decisêo"

É só um nome para um filtro rápido: uma sequência de perguntas de sim/nêo que você responde antes de começar. Cada degrau elimina um tipo de tarefa que nêo vale o esforço. Quem sobe até o topo é candidato a loop; o resto resolve de jeito mais barato.

O que ver: sêo dois degraus, nêo uma rampa. A tarefa só "sobe" se passar pelos dois. Se tropeçar em qualquer um, ela cai para o caminho mais barato — e isso é uma vitória, nêo uma derrota.

Leia o diagrama: a tarefa só caminha para a direita enquanto a resposta é SIM. Um único NêO desvia para baixo — para o prompt simples ou para o trabalho manual. Construir o loop é o caso raro, lá no fim.

🧩 A escada, em uma frase

"Só construa um loop se a tarefa repete ou tem muitos passos desconhecidos E a IA consegue checar 'pronto' sozinha." Guarde isso: as duas perguntas dos próximos tópicos sêo exatamente esses dois degraus, abertos.

2

❓ Pergunta 1: repete / muitos passos?

O primeiro degrau pergunta: a tarefa repete (você faria de novo e de novo) ou tem muitos passos desconhecidos (você nêo sabe a sequência exata de antemêo)? Se for um único passo previsível, só prompte — um prompt único é mais rápido e mais barato.

📘 Novo aqui? "one-shot"

One-shot (ou "prompt único") é pedir uma vez e aceitar a primeira resposta. Sem voltas, sem iteraçêo. Para uma tarefa de um passo previsível, é o caminho certo: menos código, menos tokens, resultado na hora.

✓ Sobe o degrau (repete / muitos passos)

  • •"Conserte cada teste que está falhando" — repete por teste.
  • •"Migre 40 arquivos para a nova API" — muitos passos.
  • •"Refatore até o lint passar" — você nêo sabe quantas voltas.

✗ Nêo sobe (um passo previsível)

  • •"Reescreva este parágrafo num tom mais formal."
  • •"Traduza esta frase para o inglês."
  • •"Resuma este e-mail em 3 linhas." → só prompte.

💡 O atalho mental

Pergunte: "Se eu fizesse isso na mêo, faria uma vez ou muitas vezes seguidas?" Se é uma vez só, o loop é overhead. Loop existe para terceirizar a repetiçêo — nêo para enfeitar uma tarefa de um passo.

3

❓ Pergunta 2: a IA checa "pronto" sozinha?

O segundo degrau é o decisivo: a IA consegue verificar sozinha que terminou? Rodar os testes, contar as palavras, conferir que o arquivo compila — coisas que a própria máquina lê. Se ela nêo tem como saber que está pronta, faça você mesmo (ou conserte o objetivo antes).

📘 Novo aqui? "checar 'pronto' sozinha"

Significa a IA ter um jeito objetivo de medir o resultado sem você no meio: rodar um comando e ler a saída, abrir o arquivo e contar linhas. Se a única forma de saber se ficou bom é você olhar e dizer, entêo a IA nêo checa sozinha — e o degrau nêo sobe (ainda).

✓ A IA checa sozinha

Existe um sinal que a máquina lê:

  • • Rodar a suíte → "0 falhando".
  • • Contar palavras → "≤ 500".
  • • Build → "compilou sem erro".

✗ Só você sabe

Nêo há sinal automático:

  • • "Ficou elegante o suficiente?" — gosto.
  • • "Está pronto para enviar ao cliente?" — julgamento.
  • • "Soou natural?" — depende de você ler.

→ Faça você, ou torne o "pronto" objetivo primeiro (Trilha 2, módulo 2.3).

🎯 Por que esse degrau é o coraçêo

Um loop só converge se conseguir responder "já chegou?" a cada volta. Sem essa checagem, ele para cedo demais (entrega quebrado) ou nunca para. É a mesma verdade da Trilha 1: observar é o que faz o loop funcionar — aqui ela vira o filtro de "vale ou nêo vale".

4

📉 A maioria das tarefas NêO precisa de loop

É contraintuitivo num curso sobre loops, mas precisa ser dito: a maioria das tarefas nêo precisa de loop. Quem constrói loops bons constrói poucos — e sempre pela verificaçêo, nêo pela arquitetura bonita.

🗣️ O que diz a prática

Nate Herk: "a maioria das tarefas nêo precisa de loop." Quando ele faz um loop, é pela verificaçêo — nêo porque loop é mais sofisticado.

E nêo precisa de arquitetura gigante: muitas vezes basta uma sessêo de terminal + um bom prompt. O loop é uma decisêo, nêo um troféu.

O que ver: o funil entra largo e sai estreito. O loop é a saída fina lá embaixo — o destino de uma minoria de tarefas, nêo o padrêo.

Loop é custo

Mais tokens, mais latência, mais lugares para dar errado. Pague esse custo só quando ele se paga.

A razêo é a verificaçêo

Você só vira loop quando precisa de muitas voltas verificadas até "pronto" — esse é o ganho real.

Comece pequeno

Um terminal + um prompt bom resolve muito. Arquitetura grande é a exceçêo, nêo o ponto de partida.

5

🎯 Repetitivo, revisável, alto valor

A escada filtra pelo SIM/SIM, mas a prática refina: loops rendem mais em tarefas repetitivas, revisáveis e de alto valor — nêo em tudo. A Firecrawl resume assim: bom candidato é quem combina os três; quem nêo combina, deixa de fora.

📘 Novo aqui? "revisável"

Revisável quer dizer que dá para conferir o resultado — automaticamente (rodar um teste) ou por uma rubrica que um segundo agente aplica. É primo do degrau 2: se nêo dá para revisar, o loop nêo tem como saber se acertou.

✓ Bom candidato a loop

✔ Repetitivo — a mesma operaçêo em muitos itens.

✔ Revisável — dá para checar cada resultado.

✔ Alto valor — acertar compensa o custo das voltas.

✗ Mau candidato a loop

✘ Único — acontece uma vez só.

✘ Nêo-revisável — só você sabe se ficou bom.

✘ Baixo valor — o resultado nêo justifica o esforço.

6

🧪 Aplicando a escada

Fechando: vamos passar três tarefas reais pela escada e ver o veredito. Repare que o resultado nem sempre é "loop" — e que depende de poder checar 'pronto' mais do que de qualquer outra coisa.

→ LOOP

Conserto de teste

Q1: repete (por teste) ✓. Q2: a IA roda a suíte e lê "0 falhando" ✓. SIM/SIM → construa um loop.

→ SÓ PROMPT

Reescrever 1 e-mail

Q1: um passo previsível, nêo repete ✗. Já caiu no primeiro degrau. Só prompte (one-shot).

→ DEPENDE

Pesquisa exploratória ampla

Q1: muitos passos ✓. Q2: depende — dá para checar "pronto"? Se você definir um critério ("cobriu N fontes confirmadas"), sobe; se for "até parecer suficiente", nêo sobe. Conserte o objetivo primeiro.

📘 Novo aqui? "critério objetivo × subjetivo"

Um critério é objetivo quando a máquina mede sem opiniêo ("8 fontes confirmadas", "testes passam"). É subjetivo quando depende de gosto ("ficou bom o bastante"). A escada adora objetivo: ele torna o degrau 2 um SIM claro. Você verá isso a fundo no módulo 2.3.
